## 当前批次：聊天控制、单供应商与设置体验

### 1. 聊天内模型与思考强度切换

目标：不必离开聊天页即可更换模型和思考强度，桌面端与手机端使用同一套语义。

- 聊天输入卡片底部显示“模型 + 当前推理档位”入口，点击后从输入框上方展开紧凑面板。
- 紧凑面板只包含“模型入口 + 推理强度滑杆”；模型列表不再与滑杆混排。
- 点击模型行进入独立的“选择模型”页，按 GPT-6、GPT-5 等家族分组，选中后返回强度面板；模型超过 4 个时列表固定高度并显示垂直滚动条。
- 模型列表来自 ChatGPT 账号的模型目录；打开面板时优先使用未过期缓存，缓存过期、缺失或当前模型未知时主动刷新目录。
- 目录刷新后当前模型不再存在时，自动切换到目录中第一个启用模型；不伪造静态模型或自定义模型入口。
- 推理强度只使用当前模型在目录中声明的 `reasoningEfforts`，不再显示固定的“默认”选项或其他模型才支持的档位。
- 推理强度使用自绘离散滑杆：绿色到黄色渐变轨道、固定尺寸白色滑块、等距档位点；滑块垂直居中，首尾与轨道贴合，拖动时不缩放；拖动时即时预览档位名称，松开后保存。
- 入口标签同步显示本地化档位名称；滑杆值使用强调色显示。
- 修改后立即保存；若当前回复仍在运行，入口禁用，避免请求中途改变配置。
- 支持点击遮罩、关闭按钮和 Escape 关闭。

验收：

- 桌面与手机都能在输入框内完成模型与推理档位切换。
- 拖动滑杆后，档位名称立即变化，松手后的下一条请求使用该档位。
- 切换模型后，输入框入口和后续请求使用新模型。
- 主面板不再展示完整模型列表；模型行进入独立分组选择页。
- 无推理等级的模型不显示滑杆，只给出说明。
- 每个模型只显示它实际支持的推理档位，不出现其他模型的档位或额外“默认”档。
- 当前等级不属于新模型时自动回到默认。

### 2. 仅保留 ChatGPT Auth

目标：移除 Anthropic 与 OpenAI API Key 两条用户接入路径。

- 默认、运行和持久化状态统一为 `chatgpt-oauth`。
- 从旧配置加载时迁移到 ChatGPT OAuth，并清理不再可见的供应商模型目录。
- 设置页删除供应商切换、API Key、MCP 服务器等不适用于该路径的入口。
- 保留底层适配器代码以避免无关的大规模删除，但 UI 不可再选择其他供应商。

验收：

- 全新安装和旧配置启动后都只走 ChatGPT OAuth。
- 设置页不存在 Anthropic、OpenAI API Key 或供应商切换入口。
- ChatGPT 登录、模型目录和聊天请求保持可用。

### 3. 设置分页与中英双语

目标：把单页设置改为按任务分组的多页结构，并提供可持久化的界面语言。

- 设置页分为：常规、模型、聊天、知识库、代理、语音、数据与诊断、关于。
- Obsidian 1.13+ 使用原生设置页面导航；旧版本使用插件自绘 TAB。
- 语言支持自动、简体中文、English；自动模式跟随 Obsidian。
- 首批覆盖设置页、聊天模型选择器、输入框与主要操作文案。
- 语言切换后立即重绘设置页，并同步更新已打开的聊天视图。

验收：

- 切换语言后设置页与聊天主要控件立即更新。
- 语言偏好写入 `data.json` 并跨重启保留。

## 第二批次：八页设置、模型偏好、代理权限与流式增强

### 目标

- 设置页按任务拆成八页，并完整支持简体中文和英语。
- 模型目录只有一个来源：ChatGPT 账号的实时/缓存模型目录，不再提供静态模型
  或自定义模型入口。
- 模型启用状态、每模型上下文窗口和上下文压缩百分比均可独立管理。
- 代理工具权限、工具启用状态与 Vault Skills 统一放在“代理”页。
- 桌面端在系统代理环境下仍然逐段显示回答；移动端保留可用的兼容回退。

### 设置页

- **常规**：插件语言、ChatGPT 账号、网络与流式状态。
- **模型**：目录状态与刷新、模型启用状态、每模型上下文窗口与恢复默认值。
- **聊天**：联网搜索、发送键、跟随编辑、最大工具步数、上下文压缩百分比。
- **知识库**：Vault 指令与知识范围说明。
- **代理**：默认工具权限、每个工具的启用与权限覆盖、Skills 管理与目录扫描。
- **语音**：ChatGPT 语音账号、音色、麦克风模式。
- **数据与诊断**：已保存聊天、调试日志、设备能力检查。
- **关于**：插件版本、作者、GitHub 仓库、上游版本、手动检查 GitHub Release。

### 数据模型

```ts
interface ModelPreference {
  enabled?: boolean;
  contextWindow?: number;
}

interface ToolPreference {
  enabled?: boolean;
  permission?: "direct" | "ask";
}

interface SkillPreference {
  enabled?: boolean;
}
```

- 缺省值表示启用；模型偏好不写入模型目录缓存，目录刷新不会丢失用户选择。
- 当前正在使用的模型不能在设置中关闭，必须先切换到另一个模型。
- 上下文窗口覆盖只影响本地窗口展示、上下文环、摘要分块和压缩阈值，不改变
  服务端真实限制。
- 上下文大小在设置页统一使用 `K`（千）和 `M`（百万）显示，不使用精确 Token
  数字。
- 旧版 `compactTokens` 在能读取模型窗口时换算为压缩百分比；不能换算时回退到
  80% 默认值，之后只保留 `compactPercent`。

### 上下文压缩

- 设置移入“聊天”页，只保留 10%–100% 的百分比滑杆与当前百分比说明。
- 默认压缩点优先使用模型目录提供的自动压缩点；目录没有时使用 80%。
- 当前模型没有窗口且没有用户覆盖值时，滑杆禁用并提示先刷新模型目录或设置
  模型上下文窗口。

### 代理与工具

- “代理”页顶部提供新工具的默认权限：`直接执行` 或 `用户批准`；默认保持现有
  行为，即 `直接执行`。
- 每个工具显示名称、类别、启用开关和权限覆盖（跟随默认/直接执行/用户批准）。
- 被禁用的工具不发送给模型；若历史请求仍调用了它，执行器返回可理解的错误，
  不产生副作用。
- 需要批准的工具在聊天中以后台模态框展示工具名和参数摘要，用户可批准或拒绝；
  拒绝结果作为工具错误返回给模型。
- `ask_user` 不再叠加批准，因为它本身就是用户交互。

### 桌面与移动网络

- 桌面端在“常规 → 网络与流式输出”提供：
  - 系统代理：优先读取环境变量，其次读取 Windows 注册表或 macOS `scutil`；
  - 手动 HTTP 代理：使用 HTTP `CONNECT` 建立 ChatGPT 的增量流式隧道，并支持手动代理 URL；
  - 直连：不读取系统代理。
- 手动代理 URL 在设置提交时校验并规范化为 `http://host:port`；无效地址不会被保存。
- 移动端不提供直连/手动代理选择，始终使用 Obsidian 原生网络栈和设备系统代理。
- 如果桌面代理隧道无法建立，流式层保留既有回退：继续通过 Obsidian `requestUrl()` 完成请求，但该路径可能是整段缓冲。

### Skills

- 默认目录改为 Vault 根目录下的 `.agents/skills`；每个子目录包含一个
  `SKILL.md`。
- 设置页可修改目录、立即重新扫描、打开技能、创建新技能，并逐个启用/停用。
- 只有启用的技能会出现在系统提示、`/` 候选和 `use_skill` 结果中。
- 如果旧配置仍指向默认的 `Skills` 目录：`.agents/skills` 存在时迁移到新目录；
  旧目录仍有技能时保留旧目录，避免已有技能消失。

### 关于与更新

- 版本与作者从 `manifest.json` 读取，仓库固定为
  `https://github.com/SuShuheng/obsidian-stark`。
- 更新检查通过 GitHub Releases API 手动触发；只显示版本状态并打开 Release，
  不自动下载或安装。
- 404、限流、离线与无 Release 均显示可恢复的状态，不影响插件使用。

### 流式输出

- 桌面端优先使用 Node HTTPS（或手动代理 `CONNECT` 隧道）进行流式传输；无法建立增量连接时才退回 `requestUrl()` 的整段缓冲。
- 回答文本在每个增量到达时更新，不等待最终响应；保持 100 ms 的 Markdown
  重绘节流。
- 聊天输入区显示明确的流式状态，回答结束后才显示复制与重新生成操作。
- 移动端若受 WebView CORS 限制只能整段接收，设置页应明确标注“当前设备为缓冲
  模式”，而不是让用户误以为请求卡住。

### 执行活动组

- 连续的工具调用收拢成一条活动行，不再为每个工具永久增加顶层消息行。
- 运行中显示最新动作与关键参数，例如“正在搜索代码 · **/README*”；工具完成、
  模型准备下一步时仍保留该行动态，直到新的助手文本或用户消息结束活动组。
- 活动组结束后按动作类别聚合为“执行了命令，已搜索代码，已读取文件”这类摘要，
  并自动收起；失败操作在摘要末尾标出数量。
- 点击活动行可展开或收起内部工具步骤；展开内容保留现有工具参数、结果与错误详情。
- 模型在工具调用前生成的简短自然语言说明保留在活动组上方，但不再附加固定的
  “执行摘要”标题。
- `reasoning.summary` 只在 ChatGPT 后端实际返回摘要事件时展示；活动组表示用户
  可见的执行过程，不会用工具名称伪造隐藏推理。

### 验收

- 八页设置均可在桌面和手机切换，所有新增文案有中英文。
- 模型列表只包含目录返回且启用的模型；新模型默认启用；当前模型不能关闭。
- 每个模型可覆盖上下文并恢复到 API 值，显示为 K/M。
- 压缩设置只有百分比；旧设置迁移后不产生无效 Token 字段。
- 工具禁用、权限覆盖、批准/拒绝和 Skills 启停均在真实代理循环中生效。
- 在系统代理环境中，桌面端回答文本增量出现；流式失败时有清晰状态。
- `npm test`、`npm run typecheck`、`npm run svelte-check` 和 `npm run build`
  全部通过。

## V1.0.1：连接恢复与主区域标签页

### 网络断流重试

- 一次对话回合内，网络断流、临时传输失败以及可恢复的 5xx/408 请求最多自动
  重新发送 5 次；初次请求之外共有 5 次重试机会。
- ChatGPT OAuth 的传输失败按同一规则处理；HTTP 400、401/403 等不可恢复响应
  不会被 5 次网络重试捕获，仍沿用原有的兼容性降级或重新登录提示。
- 已经可能触发远端工具副作用的请求不自动重发，避免重复执行。

验收：网络持续失败时，同一回合最多观察到 6 次请求尝试，随后显示最终错误；
HTTP 400 不进入网络重试循环。

### 主区域标签页

- 右侧栏聊天保持原有入口和默认行为。
- “打开聊天”仍定位右侧栏；“在新标签页打开聊天”使用主编辑区标签页，并通过
  命令面板与功能区菜单提供入口。
- 主区域标签页存在时再次打开会复用该标签页，不重复创建；侧栏和标签页共享
  同一会话、运行状态和设置。

验收：桌面端可同时保留侧栏与主区域聊天；重复执行“新标签页”命令不会创建第二个
主区域聊天标签页，命令更新会同步到所有已打开的聊天视图。
